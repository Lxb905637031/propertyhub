# PropertyHub 产品说明

## 1. 产品定位

PropertyHub 是一个面向物业集团的企业采购与积分福利商城。它把企业采购、普通购买和积分兑换放在同一套商品、库存、订单和履约体系中，目标是让一笔业务从选品开始，到审批、支付、发货、售后和对账都可追踪。

首版以低成本、可演示、可上线为目标。支付、短信、ERP 和物流使用 Mock Provider，不依赖第三方商户资质或商务接口；微信小程序和真实支付不在当前版本。

## 2. 用户角色

| 角色 | 主要任务 |
| --- | --- |
| 平台管理员 | 管理租户、系统配置和审计信息 |
| 租户管理员 | 管理组织、成员、角色、商品和库存 |
| 采购员 | 创建企业采购申请并跟踪订单 |
| 审批人 | 按组织和金额审批采购申请 |
| 仓库人员 | 锁定库存、拣货、发货和处理异常 |
| 财务人员 | 查看订单、退款、结算和对账差异 |
| 员工/住户 | 浏览商品、下单、使用积分兑换和申请售后 |

## 3. 产品如何使用

### 3.1 企业采购

1. 租户管理员创建物业项目、成员、角色和审批规则。
2. 运营人员发布商品、SKU、企业价格和库存。
3. 采购员把物资加入采购单，提交采购申请。
4. 系统根据组织和金额匹配审批节点。
5. 审批通过后创建订单并锁定库存。
6. 使用模拟支付完成支付，支付回调幂等地推进订单状态。
7. 仓库人员发货，Mock 物流生成运单和轨迹。
8. 采购员确认收货，财务在报表中完成对账。

### 3.2 普通购买

1. 员工/住户浏览已上架商品。
2. 选择 SKU、数量和收货地址，加入购物车。
3. 结算时校验价格、库存、优惠券和积分。
4. 创建订单并锁定库存。
5. 点击模拟支付，选择成功、失败或超时场景。
6. 系统接收模拟回调，防止重复扣库存。
7. 仓库发货，用户查看模拟物流轨迹并确认收货。
8. 用户可以发起退款或退货，系统按状态机处理库存和金额。

### 3.3 积分兑换

1. 用户查看积分商品和兑换规则。
2. 下单时冻结积分并锁定库存。
3. 订单支付方式为积分或积分加模拟现金。
4. 订单发货并完成后，积分正式扣减。
5. 订单取消、支付超时或售后通过时，按规则释放或返还积分。

## 4. 核心业务闭环

```text
登录
  -> 商品发布
  -> SKU 与库存配置
  -> 浏览/采购/兑换
  -> 购物车结算
  -> 审批（企业采购）
  -> 创建订单
  -> 锁定库存与积分
  -> 模拟支付
  -> 模拟支付回调
  -> 发货与模拟物流
  -> 确认收货
  -> 售后/退款
  -> 报表与对账
```

## 5. 项目创造的价值

### 对业务

- 将采购申请、审批、库存、订单、履约、售后和财务对账串成一条链路。
- 让采购过程具有可追踪、可审批和可审计能力。
- 减少库存不准确、重复采购和人工核对的成本。
- 用积分兑换覆盖员工/住户福利场景，让平台不只是普通电商。

### 对工程交付

- 体现企业级领域建模，而不是只实现商品列表和购物车。
- 通过订单、库存和支付展示事务、幂等、并发和数据一致性。
- 通过 Mock Provider 展示外部系统适配、异步任务、重试、死信和对账。
- 通过测试、部署、日志、健康检查和回滚展示完整交付能力。

## 6. 首版功能范围

### P0：必须完成

- 登录、租户和基础角色权限。
- 商品、分类、SPU、SKU、价格和上下架。
- 仓库、库存、锁库存、扣库存、释放库存和库存流水。
- 购物车、结算和订单状态机。
- Mock 支付、回调签名校验和回调幂等。
- 发货、Mock 物流、确认收货和基础退款。
- 管理后台、种子数据和核心 E2E 链路。

### P1：体现 B 端能力

- 采购申请和多级审批。
- 积分账户、冻结、扣减和返还。
- 优惠券、混合支付和价格策略。
- 报表、导出、对账差异和审计日志。
- Mock 短信、站内通知、任务重试和失败记录。

### P2：扩展能力

- Mock ERP 的批量导入导出和 Webhook 同步。
- 多仓库和供应商协同。
- 私有化部署文档。
- 替换为真实支付、物流、短信或客户 ERP 的 Provider 实现。

## 7. 明确不做

- 微信小程序。
- 真实微信支付或支付宝支付。
- 真实短信发送。
- 需要商务合同的真实 ERP 和物流接口。
- 复杂营销中台和大规模推荐算法。

## 8. Mock Provider 如何工作

### MockPaymentProvider

支付页面生成支付流水号，并通过测试参数决定成功、失败或超时。回调接口仍然执行签名校验、幂等键判断和合法订单状态推进。重复回调必须返回幂等成功，不能重复扣库存或积分。

### MockSmsProvider

不连接短信网关。发送动作写入通知记录和开发环境 outbox，前台展示站内通知，后台可以查看模板、接收人、发送状态和失败原因。

### MockErpProvider

通过 JSON/CSV 文件和本地 Webhook 模拟商品、库存和订单同步。同步任务进入队列，支持成功、失败、超时、重试、死信和人工重放。

### MockLogisticsProvider

发货时创建模拟运单号，按时间或后台操作推进已揽收、运输中、派送中、已签收和异常状态。

## 9. 面试演示路径

使用种子账号完成以下演示：

1. 租户管理员登录并查看组织和权限。
2. 管理员发布一个 SKU 并初始化库存。
3. 普通用户把商品加入购物车并创建订单。
4. 选择模拟支付成功，观察订单和库存变化。
5. 重复触发支付回调，证明不会重复扣减。
6. 仓库人员发货，查看模拟物流轨迹。
7. 用户确认收货并发起退款。
8. 管理员查看库存流水、订单报表和审计日志。

## 10. 后续替换真实服务

核心订单、库存和售后模块只依赖 Provider 接口，不依赖具体厂商。未来增加真实服务时，只需要：

1. 实现对应 Provider。
2. 增加环境变量和密钥配置。
3. 增加签名、回调和异常映射测试。
4. 通过配置切换 Provider。
5. 保留 Mock Provider 作为本地开发和回归测试实现。
